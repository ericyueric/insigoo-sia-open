## 这是什么

insigoo-sia 是一个 AI 技能包（Skill），把 **insigoo SIA 社会影响力评估框架** 变成 AI 可直接执行的评估流程。把公益项目方案或执行材料喂给它，它会像体检医生一样输出**带优先级的诊断报告与处方**。

**v3.2.0 起，本项目全面取消付费层**：L1 逻辑自洽、L2 指标量化（完整评分锚点 / 证据五级定级规则 / 标杆案例库 / 五类参考指标集）、L3 价值评估层设计草案、D 线主体评估轴，全部随包开源、可离线运行，无付费墙、无按次计费、不依赖任何外部服务。历史上的付费版产品线与计费链路已整体退出，本仓库是唯一发行版。

## 体系一览

| 层级                  | 回答的问题                    | 状态                                          | 开放情况                 |
| ------------------- | ------------------------ | ------------------------------------------- | -------------------- |
| **L1 逻辑自洽层**       | 逻辑讲得通吗？                  | ✅ 稳定（100 项目实测）                             | ✅ 全开源                |
| **L2 指标量化层**       | 成果量得出吗？证据有多强？           | ✅ 稳定（四维 D1-D4 + 证据五级 A-E）                 | ✅ 全开源                |
| **L3 价值评估层**       | 值多少？                     | 🧪 **v0.3 方法草案**（双轨制 · 方法演示已完成）             | ✅ 全文 + 参考实现 + 验证案例开放 |
| **D 线主体评估轴**       | 把钱给这个主体值不值得？            | ✅ 规格定稿（D0 发起人 / D1 组织八维 / D2 成果核验）       | ✅ 全量免费开源             |

> D 线与 L1–L3 **平行**，不是 L4：L 线评「干预设计」，D 线评「主体信用」，最终资助建议 = 项目线得分 × 主体线风险矩阵。

> **关于 L3 的定位说明**：L3 是**方法草案，不是行业标准**。  
> 货币化轨道目前全样本库仅 1 个 L2-A 验证案例，v0.2 §8 的四项待办尚未闭合。  
> 单一案例能证明方法跑得通，不能证明方法已稳定——把它称做"标准"，会把未验证的方法变成可被审计质疑的承诺。  
> 我们选择诚实标注成熟度，这既是对使用方负责，也符合本框架自己的「诚实归因」原则。

### L2 四维评分结构

```
L2 总分 = D1(25) + D2(30) + D3(25) + D4(20)，满分 100
```

| 维度         |  权重 | 核心问题                       |
| ---------- | :-: | -------------------------- |
| D1 成果指标质量  |  25 | 指标对准的是"成果"还是"产出"？          |
| D2 证据强度评级  |  30 | 证据有多硬？（A 独立因果验证 → E 无有效证据） |
| D3 因果链数据覆盖 |  25 | ToC 上有多少关键节点真有数据？          |
| D4 测量方法可信度 |  20 | 数据是怎么测出来的？                 |

分级：L2-A（85-100 深度验证级）/ L2-B（70-84 量化可信级）/ L2-C（50-69 指标初建级）/ L2-D（<50 未达标级）。  
**一票否决**：证据定 E 级时，无论总分多少最高只能判 L2-C。

### L3 双轨制（v0.3 草案）

- **货币化轨道**（仅 L2-A）：SROI 元:元，≥2 种货币化方法交叉验证，给区间不给单点值；须经专业人员复核后方可正式发布
- **叙事轨道**（开放层 · L2-B/C）：证据强度陈述 + Contribution 声明，必须回答"没有这个项目会怎样"

**反事实四系数**（把 L1 的定性归因升级为可审计的量化算子）：

```
净贡献率 = (1 − Deadweight) × (1 − Attribution) × (1 − Displacement) × (1 − Drop-off)
          没你也会发生     别人的功劳别抢     把问题推给了别处     三年后还剩几成
```

**⚠️ 使用 L3 前必读**：`references/l3/l3-redline-double-deduction.md`

第三方专业机构发布的 SROI，绝大多数**已经内含**四系数调整。若再乘以本项目的自估净贡献率，就是把同一笔扣减做了两次——  
错误方向是**低估**，因此特别隐蔽：它会安静地产出一个看起来很保守、无人质疑的错数字。  
参考实现 `l3-calculator.ts` 对此实现了毛/净口径判定守卫，口径不明时按保守原则不派生。

## 怎么用

1. 把本目录放到你的 AI 助手的 skills 目录（WorkBuddy：`~/.workbuddy/skills/`；其他助手按各自约定）
2. 直接对话：
   - L1：`帮我体检一下这个项目` / `快速自检` / `评审这 5 份申请`
   - L2：`深度评估一下 XX 项目` / `证据有多强` / `指标盘点`
   - D 线：`组织尽调` / `发起人尽调` / `主体评估` / `KYC` / `KYB` / `KYI`
3. L2 有硬门槛：项目须先通过 L1（快检 ≥6 分 / 完整体检基础期及以上 / 3-5.5 分但 Q3Q4Q7 均达标），未通过会被退回先做 L1。

**离线可用**：全流程不联网、不依赖任何外部服务。若想与 223 个项目库做同类目对标，可**选配**接入 `sia-kb` MCP Server（见下节）。

## 服务端形态（选配 · 自有云）

本技能包可完全离线独立运行。若要做同类目对标或复用已有评估数据，可**选配**接入两个服务端形态，二者均部署于 **insigoo 自有云服务器**（`www.insigoo.com.cn` 为本项目自有官网）：

| 形态                   | 技术栈                                                          | 能力                                                                                                                                                        |
| -------------------- | ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sia-kb` MCP Server  | TypeScript + `@modelcontextprotocol/sdk` + stdio + zod + 只读 PostgreSQL | 7 工具：`list_projects` / `get_project` / `get_indicators` / `search_kb` / `l3_signals` / `get_counterfactual` / `generate_report`                                  |
| REST API             | FastAPI + psycopg                                             | 7 端点：`/health` / `/projects` / `/projects/{id}` / `/indicators` / `/l3/signals` / `/l3/counterfactual/{id}` / `/report/{id}`                                   |

可公开的接口约定、计算内核与环境变量模板见 `server/`。完整生产源码（数据层、工具注册层、检索桥接、REST 主程序）因仍含生产凭据与内部网络地址，**须先完成凭据清理方可开放**——在公开仓库泄露凭据的代价远大于晚几天放出，故本版先开放可安全公开的部分。

WorkBuddy 用户可在 `~/.workbuddy/mcp.json` 增加 `sia-kb` 条目后重载生效；**未接入不影响 L1/L2 评估完整性**。

## 使用边界

- 本框架是 **发展性评估工具**，不是审计工具，**不得用于财务/合规/问责审计**
- 输出为 **AI 辅助评估初稿**（AI 初评 + 人工复核质控），重大资助决策需结合人工尽调与专家判断
- L3 货币化轨道不建议在 L2-A 以下项目出具
- `sia_kb` 项目库原始采集数据不在本许可范围内：本仓库仅引用脱敏聚合统计，不分发原始数据（详见 `NOTICE.md`）

## 开放范围与保留边界

自 v3.2.0 起，本项目不设付费层，方法论资产全量开放：

| 类别      | 内容                                                                                                                                                                                 |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ✅ 已开放  | L1 / L2（评分锚点、证据定级、标杆案例、五类指标集、机器可读评分表）/ L3 设计草案与参考实现 / D 线主体评估轴（JSON 评分卡 + 4 个可读拆分）/ 报告模板 / `server/` 可公开服务端资产                                                  |
| ⛔ 合规保留 | 223 个项目的**原始采集数据**：采集自腾讯公益 / 支付宝公益 / 慈善中国等平台公开页面，不构成本仓库的方法论部分；本仓库不分发原始数据，仅引用脱敏聚合统计（口径见 `NOTICE.md` §2）                                                       |
| ⛔ 隐私保留 | 含第三方姓名、合作分成条款的内部文档                                                                                                                                                              |
| ⏳ 待开放  | 生产服务端完整源码：数据层等文件含生产凭据与内部网络地址，待凭据清理后开放（详见 `server/README.md`）                                                                                                                  |

以上保留项**不影响本包的独立使用**；前两类属**不能**开放，不是不愿开放。
